# Inline every single-use function — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** No unexported function or method in the tree has exactly one call site. Each is folded into its caller, body verbatim, and its tests move to the nearest entry point that survives.

**Architecture:** A pure inlining pass, package by package, leaves first and the command root last. Interface-satisfying methods, exported identifiers, and anything with two or more callers stay. Types stay even when their only method is single-use, because a method that satisfies an interface is not a call site. Two structural side effects, both on the user's direction: `tunnel.go` empties into `builder.go`'s `Command` and is deleted with its test file, and the root's two remaining structs become contracts with implementations elsewhere (`Binder` in `attach`, `CacheDirs` in `cachedir`), so `origins.go` goes too. The root ends with four source files. Behaviour through the command line is unchanged; this is verified the same way the previous refactor was.

**Tech Stack:** Go 1.26 · libtunnel v0.0.66 · cobra/pflag/viper · cri-streaming · moby · pkg/browser

**Decisions** (made with the user on 2026-09-06, in place of a spec):

- *Literal everything.* The user was shown the consequence — `Build` absorbs `command`, `versionCommand`, `run` and its helpers (~550 lines); `docker.TargetsImpl.Open` ~160; `attach.Serve` ~200; `panel.Interceptors` ~250 — and chose it over keeping `run` or inlining leaves only.
- *Tests move to the caller, never away.* A test that targeted an inlined helper is rewritten against the nearest remaining entry point with every assertion it made preserved. The reviewer's gate is parity against `git show <base>:<test file>`.
- *Two tables lose their seam and are dropped, recorded in the commit message:* `TestVCSVersion` (four `debug.BuildInfo` cases; `Version` reads the real build info) and `TestSelfIDs` (five mountinfo-ordering cases; reachable only through a daemon-backed `Open`, which `TestOpenScopesByMountinfo` already exercises for one shape).
- *`run`'s logger writes to `os.Stderr`, not the command's writer* (pre-existing; the previous branch's final reviewer flagged it). Tests that used to read `b.logger()` and `b.events(...)` capture `os.Stderr` through a pipe for the duration of one `Execute`. Fixing the destination is a separate change and is not done here.
- *Naming, audited on the user's request (19:23):* `Build()` → `Command()` — it returns a `*cobra.Command` and "build" was the fluent era's verb; `panel`'s `shell*` → `page*` and `shellOrigin` → `tile`, matching `attach`'s vocabulary; `Cache.Cached()` → `Load()`, the verb pairing with `Save`; after the root collapse the file that holds the origin binding type and `PublicURL` is `origins.go` and the type is `origins`; `docker.selfRefsMax` → `candidateIDsMax` because it named a function that no longer exists. `Targets`, `Builder`, `Logger()` and `TestRun` keep their names.
- *No struct in the root but `BuilderImpl` (user, 20:34).* `bound`/`origins` becomes a contract: `Binder.Bind(ctx, display, log) (dialable []*url.URL, close io.Closer, err error)` in the root, implemented by `attach.BinderImpl` (which owns `Serve`); `Targets` moves into `attach` as the binder's dependency and `docker` asserts it there; the root's `Targets`/`WithTargets`/`targets` become `Binder`/`WithBinder`/`binder`. `cacheDirValue` becomes `v1alpha1/cachedir` — `ValueImpl` owning the list and the entry rules, behind a root `CacheDirs` contract (`pflag.Value` + `pflag.SliceValue` + `Add`). After Task 8 the root is four source files: `v1alpha1.go`, `builder.go`, `env.go`, `version.go`.
- *`examples/attach`'s `run` is inlined by restructuring `main`* so the container teardown runs before `os.Exit`, since a deferred call would be skipped. `examples/multi-origin`'s `serve` and `examples/docker-compose`'s `sh` have two callers and stay.

## Global Constraints

- **Branch `refactor/contracts`, HEAD cdbbc19 at start.** Same branch as the contracts refactor; the user reviews both together. Never push; no PR — the user has said they will say when.
- **Body verbatim.** An inlined function's statements move unchanged. Its parameters become the caller's variables (rename only where a name collides); its `return x` becomes an assignment or falls through; early returns inside a loop become `continue`/labelled forms only when the control flow forces it, and the commit message names each such spot.
- **Doc comments survive.** The function's doc comment becomes a comment block at the inlined location, reworded only where it referred to the function by name ("bindOrigins turns…" → "Turn…"). The "why" in these comments is the codebase's institutional memory; deleting it is a finding.
- **One test file per source file**, and a test file follows its source through a deletion: `tunnel.go` and `origins.go` go, so their tests move to `builder_test.go` (the `RunE` they drive, and `PublicURL`, live in `Command`'s file) and `attach_test.go` (the binding).
- **Every task ends green:** `gofmt -l .` empty; `go vet ./...`; `go build ./...`; `go test ./...`; and for the package touched, `go test -race ./<pkg>/`. Task 10 runs `make all` and `make race`.
- **No behaviour change.** Flags, env mirrors, help text, stderr lines, exit codes identical. `main.go` untouched. `go.mod` untouched.
- **Stage by name**, never `git add -A`. Commit after every task with the trailer below. `git log --format=%G?` prints `U` for this repo's signed commits — good signature, unknown validity, not a failure.
